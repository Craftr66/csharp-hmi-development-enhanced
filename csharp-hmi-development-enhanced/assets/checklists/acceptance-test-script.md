# 验收测试脚本模板

## 测试目标

为上位机软件提供可执行的验收测试脚本，覆盖正常流程、边界条件、异常场景，确保交付质量。

## 测试环境准备

### 硬件准备

- [ ] 目标设备已上电并处于正常工作状态
- [ ] 通信线缆连接正确（串口/网口）
- [ ] 测试用传感器/执行器已连接
- [ ] 备用设备准备（用于故障模拟）

### 软件准备

- [ ] 被测软件已安装在测试机
- [ ] 测试数据文件已准备（模拟数据、边界值数据）
- [ ] 数据库已初始化（清空或导入基线数据）
- [ ] 日志目录已清空，便于问题追溯

### 工具准备

- [ ] 串口调试助手 / Modbus Poll（用于模拟设备）
- [ ] Wireshark / Fiddler（网络抓包）
- [ ] Process Explorer（监控内存/句柄）
- [ ] 秒表或性能分析工具

### 第二类：边界与压力测试

#### TC-05：长时间运行测试

**测试目的**：验证软件能稳定运行 72 小时

**执行方法**：
1. 运行 `scripts/long_run_monitor.py --process-name "YourApp.exe" --duration 72`
2. 让软件持续采集（可降低采样率到 10Hz 减少设备负担）
3. 72 小时后检查报告

**通过标准**：
- [ ] 内存增长 < 5%
- [ ] 句柄数无明显增长
- [ ] CPU 平均占用 < 30%
- [ ] 无崩溃、无卡死

## 自动化测试脚本示例

### 数据注入脚本（Python）

用于模拟设备发送测试数据：

```python
import serial
import time
import struct

def send_test_data(port_name, device_address, temperature_value):
    """模拟温控器发送温度数据"""
    port = serial.Serial(port_name, 9600, timeout=1)
    
    # 构造报文（参考协议）
    data = bytearray([
        0xAA, 0x55,  # 帧头
        device_address,  # 设备地址
        0x03,  # 功能码（响应）
        0x02,  # 数据长度
        (temperature_value * 10) >> 8,  # 温度高字节
        (temperature_value * 10) & 0xFF,  # 温度低字节
    ])
    
    # 计算校验和
    checksum = 0
    for i in range(2, len(data)):
        checksum ^= data[i]
    data.append(checksum)
    
    port.write(data)
    port.close()

# 测试用例：注入一组温度数据
for temp in [20.0, 25.0, 30.0, 35.0, 40.0]:
    send_test_data('COM3', 0x01, temp)
    time.sleep(1)
```

### 失败用例详情

**TC-02-边界测试：采样率 100Hz**
- 现象：实际采样率只有 85Hz，CPU 占用 60%
- 原因：数据库批量写入未优化
- 整改措施：改用异步队列批量写入，攒够 100 条再写
- 预计修复时间：2 天

**TC-08：设备掉电恢复**
- 现象：设备掉电后重连失败，需手动重启软件
- 原因：串口句柄未正确释放
- 整改措施：在 Dispose 中强制关闭串口
- 预计修复时间：1 天

**TC-10：磁盘满测试**
- 现象：磁盘满后软件崩溃退出
- 原因：未捕获 IOException
- 整改措施：添加异常处理，降级为只显示不存储
- 预计修复时间：半天

### 测试结论

软件基本功能完整，核心流程稳定，但在极限采样率和异常处理方面需要加强。建议修复上述 3 个问题后再次测试。
